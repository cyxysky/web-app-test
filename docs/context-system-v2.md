# 对话上下文系统

压缩产物是“语义任务状态 + 可回读材料引用 + 必要的近期工作内容”。原始记录负责可恢复性，任务状态负责连续性，请求组装器控制本轮实际发送的内容。

## 压缩流程

1. SDK 原始消息保存为不可变记录，包括工具调用参数、结果和 provider 的推理及签名。请求视图不覆盖原始记录。
2. 按完整工具交换选择待归档内容。调用与结果整体保留或归档，不改写签名链中的源码参数。
3. 程序提取源码、补丁和 Skill 引用，再把正文移出摘要输入。用户代码块周围的要求仍保留；混合工具结果中的相邻错误信息继续提供给摘要模型。
4. 摘要模型读取上一份状态、处理后的增量记录和运行时观测，重新整理当前任务。按完整交换分批；单组放不下时保留原记录，不截掉半条要求。
5. 校验结构、引用、用户指令覆盖及旧的有效约束；失败重试一次。未通过校验的用户要求和普通交换继续保留，源码及大 Skill 可独立换成回读引用。
6. 使用接受的状态重新组装，只归档已确认覆盖的普通交换，最新用户消息继续保留。保存实际请求清单与恢复检查点。

目标大小是软目标，不能为了凑长度丢弃有效约束。超过安全输入预算时明确报错，不静默截断指令。

## 语义任务状态

continuationSummary 使用版本 2 JSON：

| 字段 | 含义 |
| --- | --- |
| goal / currentState | 当前目标和工作状态 |
| constraints | 有效要求、用户纠正、交付约束 |
| completed | 带证据引用的已验证完成事项 |
| decisions | 影响后续选择的决定及必要原因 |
| keyFacts | 关键事实、数值与单位、产物 ID |
| failedAttempts | 失败、空结果及适用条件 |
| openItems / nextActions | 未完成事项、下一步及需要回读的引用 |
| instructionCoverage | 用户消息如何保留、被替代或完成 |

条目带 sourceRefs，可带 status 和 requires。列表每次重新整理，不永久追加。旧的有效约束必须继续有来源覆盖，或说明为何被替代、完成。提示词要求区分已验证、尝试过、未知及待办；工具成功不等于整体任务完成，结果未知的写入先查现状。

程序只能检查结构、引用与覆盖关系，不能证明自然语言摘要完全正确。原记录始终保留，缺失证据安排回读。检查点不再按字符数截断 JSON，常规续接状态更新不会把版本 2 降回旧摘要格式。

## 源码引用

runtime-context-materials.ts 从实际参数和返回元数据提取：

- 原始 ctx_ 消息引用与 JSON Pointer。
- documentId、产物 ID、路径、sourceUnitPath、源码文件名。
- 实际开始/结束行号、坐标空间、版本及散列，包括编辑校验的 patchBaseDigest。
- 回读方式：文档使用 file.readSource，历史消息使用 contextRead。

缺少字段时不补造。文件再大也不交给摘要模型保存全文；编辑前重新读取当前源码，按源单元和行范围取需要的部分。历史引用不代表实时文件状态。

contextRead 支持 JSON Pointer、字符分页、搜索和散列；预览或分页明确标记 complete: false，不能当作完整读取。大工具结果的摘要输入可以是有界预览，同时保留原始记录入口。

最近材料引用进入请求，完整注册表保存在任务状态。源码和大 Skill 一旦归档，SDK 再次传入旧历史也不会令正文复活；新一次读取产生新引用，可供后续操作。

## Skill 正文与缓存

“已缓存”“历史上读过”“当前请求包含正文”分别处理：

- 默认正文阈值为 2,000 个估算 tokens。小 Skill 优先整篇保留；内置 Skill 只保留同一 ID 最新的读取。如果与源码或大 Skill 同属不可拆分的工具交换，则整组归档并留下回读入口。
- 大 Skill 只留 ID、版本/散列和读取方式，需要其能力时重新读取。简介用于选择，不能代替操作规则。
- 内置能力门禁检查最终请求中的完整、当前版本正文。缺失时先返回 Skill，不执行受管操作；模型看完后下一步才可执行。同轮读取回执不能提前放行并行调用。
- 用户 Skill 持久化 id/version/digest/loadedAt/bodyAvailable。最终组装更新 bodyAvailable；压缩后再次读取恢复正文，缓存命中不能只回复“以前读过”。
- 刚重读的正文进入后续普通请求，到下一次压缩再处理。必要正文和要求本身超过安全预算时明确报错。
- 用户 Skill 的 content.resources 用于独立参考资料，不自动猜测和裁剪 Markdown 操作规则。

当前三个包实际导出的运行时 Skill 大小（2026-09-05）：

| 包 | 字符数 | UTF-8 字节 | 估算 tokens | 默认处理 |
| --- | ---: | ---: | ---: | --- |
| file | 65,790 | 66,582 | 16,745 | 压缩后按需重读 |
| chart | 7,619 | 7,852 | 1,993 | 优先完整保留 |
| browser | 28,118 | 28,176 | 7,052 | 压缩后按需重读 |

测量对象是导出的 Skill 正文，不是包或 TypeScript 文件大小。token 数使用项目估算器，不是供应商 tokenizer 精确结果。chart 接近阈值，内容增长后自动转入大 Skill 策略。

以上适用于原生 SDK Agent。现有 Codex 对象调用通道没有相同的归档/contextRead 协议，继续使用其原有读取状态与资料携带方式。

## 存储和恢复

- browser_chat_context_record 按会话与内容引用保存不可变消息；相同正文只存一次，历史事件位置保留。
- modelContext.version = 2 的 history/active 是引用列表，旧会话加载转换，下次保存写入新格式。
- taskState 保存用户指令、最近工具观测、未完成调用、summarizedRefs、archivedRefs、compactedRefs 和 materials。
- browser_chat_context_request 保存实际发送引用、选择原因、模型配置、系统提示/工具定义引用和知识选择结果。
- 记录和快照索引事务提交；请求前、待执行调用及工具完成后设置检查点。分支各自维护状态。
- 既有迁移 1788566400000-browser-chat-context-records.ts 支持 SQLite/PostgreSQL。本次字段存于现有 JSON，无需额外迁移。

## 预算设置

| 设置 | 默认值 | 用途 |
| --- | ---: | --- |
| AI_CONTEXT_COMPRESSION_TRIGGER_TOKENS | 200000 | 触发值，不高于安全输入预算 |
| AI_CONTEXT_COMPRESSION_TARGET_RATIO | 0.25 | 相对触发值的软目标比例 |
| AI_CONTEXT_SKILL_INLINE_TOKENS | 2000 | 小 Skill 正文阈值，可设 0 |
| AI_CONTEXT_MODEL_PROFILES | 模型默认配置 | 窗口、输出预留、图片估算 |

安全输入预算为 min(window × 85%, window − outputReserve − safety)，安全余量为窗口的 5%（至少 1024 tokens）。显式 provider 输出上限计入预留。

这些设置控制上下文组装，不向业务请求注入全局 max_tokens，也不修改用户的 thinking 或 max_completion_tokens。finish_reason=length 的输出限制与输入上下文压缩是两个问题。

## 记忆与用户 Skill 检索

记忆和用户 Skill 通过 RuntimeKnowledgeBlock 逐项提供 ID、版本、散列、原因、缓存命中及大小。旧知识快照从请求移除，装入当前有效版本。

自动候选默认最多 8 个，显式选择的未读目录项保持可见；正文由读取动作加载。可选记忆和候选共享 min(8000, 安全输入预算 × 8%) 软预算，超额整项省略。压缩时的小用户 Skill 也参与预算选择，省略正文后留下回读入口。

每个模型步骤检查目录版本、权限及启停状态；缓存按用户、任务、站点和数据版本隔离。删除、停用和撤销共享会移除规则，更新在步骤边界加载。

记忆沿用本地中英文召回与冲突处理，默认最多 6 条，其中最多 2 条留给常用偏好，其余要求任务相关。使用次数只在最终请求选中后记录，不修改内容时间或额外增加召回分。写入以当前用户消息为证据，辅助材料整条省略，不截断 JSON。

## 日志与验证

压缩日志包含策略 semantic-state-with-source-and-skill-references、触发和目标大小、前后估算、摘要未完成状态及原因。实际请求清单独立持久化，前端通过既有 /api/browser-chat/:sessionId/context?requestId=... 入口读取。
